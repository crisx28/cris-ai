Seven concrete issues

1

Truncated client name, no way to read it

Worse now
On the chart, Nicholas Ble… clips mid-name with no tooltip, no title attribute, no expand. The full name (Nicholas Bletsis or similar) is simply unavailable from this view. Checked against the live build: adding the lead_builder tag next to each name ate into the same column with no width adjustment — Nathan Dart now renders as Nathan… and Maria Florou as Maria…, neither of which clipped before. The fix list below got longer, not shorter.
Fix Add a title attribute for hover, or let the label wrap to a second line instead of clipping — a Gantt row has vertical room, a fixed single-line label doesn't need to fight for it.
2

Row heights aren't fixed — the grid doesn't line up

Still open
Nathan Dart's left-column metadata is 3 lines (name, company, kickoff). Maria Florou's and Danielle Dwyer's are 4 (name, kickoff, scope/SOW line, access-ready line). Each row is a different height, so the bars beside them sit at inconsistent vertical positions — the thing that makes a Gantt scannable at a glance.
Fix Give every row a fixed min-height sized to the longest realistic metadata block (4 lines), or truncate the metadata line itself to one summary line with the rest on hover — don't let the bar's vertical position depend on how much text a client happens to have.
3

"Awaiting kickoff" list has no urgency signal

Still open
Helen Nguyen, Dylan Yard, Sof and Chris, Lance Vale, Emma Cattell, Julio Rojas, Damian Burstow, Dan White, Morgan Nelson all read No dates set yet in identical gray text — same visual weight as Jess Plane (Scope call 5 Sept) or Angelina Badri (Scope call 22 July, over a month overdue relative to the other dates on screen).
Fix This is exactly the signal the automation work computes — Angelina's scope call is old enough to be worth a different color or a small flag, and "no dates set" is a different state from "scope call booked." Don't wait for the capacity tile to surface this; group or color this list by state now.
4

Bars clip at the right edge with no signal there's more

Still open
Danielle Dwyer's Pre-Build bar (blue) runs to 12 Oct/1 Oct but the visible date axis stops at 28 Sept — the bar is cut off flush against the container edge. Nothing on the chart itself hints there's more; only a thin horizontal scrollbar at the very bottom gives it away, and it's easy to miss entirely.
Fix A fade gradient or a small ">" chevron at the container's right edge whenever a bar's end date exceeds the visible range — cheap to add, and it's the same edge where Jack's new OOO lane and the open-capacity marker are about to render, so worth fixing before those land there too.
5

The "tentative" bar has no label on the bar itself

Still open
Nicholas's dashed, unfilled bar is the only visual cue that his kickoff is tentative — the word "(tentative)" only appears as small aside text in the left column, several lines down from the bar it describes. Easy to miss when scanning bars left to right.
Fix Put the state name on or directly above the bar itself. This matters beyond this one case: the automation spec (section 07) proposes reusing this exact dashed idiom for the new "open window" marker — if the tentative state is already easy to miss here, the new one will be too, unless this gets fixed first rather than copied.
6

Four segment colors, all warm, distinguished by hue alone

Still open
Scope (amber), Pre-Build (blue), Build (lime), Refinement (olive) — scope and refinement in particular sit close enough in hue/lightness to be hard to tell apart at a glance, especially for anyone with a color-vision deficiency, and there's no secondary cue (pattern, label, icon).
Fix Add a secondary encoding — even just a label on hover or a subtly different fill texture — before the automation work adds an OOO color and an open-capacity accent on top of these four. Six similar-toned colors with no backup cue is a harder problem than four.
7

Legend sits disconnected, far below the chart

Worse now
The color-key legend (scope/pre-build/build/refinement) is the last thing on the page, separated from the chart it explains by the full height of all visible rows — someone has to scroll past everything to find out what a color means. Checked against the live build: it now has six entries (OOO and open-capacity got added), still at the very bottom — exactly the growth this finding warned about, landed without the relocation.
Fix Move it adjacent to the chart header, or make it sticky. It's about to grow to six entries (OOO, open window) — worth relocating now rather than after it's longer and even easier to miss.
02

What actually shipped well

Worth saying plainly, not just cataloguing what's wrong: the capacity tile, lead_builder badges, and the open-capacity marker are all live and match the automation spec — real numbers, informational-only framing, no fabricated data. That part of the work is done and done right. The layout debt below is a separate, still-open piece of work, not a sign anything functional is broken.

03

Why this still matters, now that it's live

This isn't hypothetical anymore — it happened. Adding the builder tag without adjusting the name column is exactly the kind of collision this doc warned about in issue 1, and it's why issue 7 (legend) is worse, not just unaddressed: both predicted exactly what a new state landing on unfixed layout would do. None of this blocks using the page — it's legible, just not clean — but it's worth a dedicated pass rather than absorbing more debt each time a new state gets added.
